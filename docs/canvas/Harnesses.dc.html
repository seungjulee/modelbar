Harnesses

Picking a model in the menu writes that harness's own config. The point is that adding a model to the manifest is enough — it no longer means hand-editing six files.

A model whose backend doesn't serve the required format stays visible but disabled, with the reason attached. No amount of config writing fixes a protocol mismatch — it just relocates the failure to the first request.

Registration, then the pointer

Always in that order, and the pointer only moves if registration succeeded — pointing a harness at a provider it has no definition for is exactly the broken state this prevents. Registration is idempotent: selecting a model that is already defined rewrites its definition to match the manifest rather than appending a duplicate.

Claude Code is deliberately different

Nothing here ever writes ~/.claude/settings.json or changes what a bare claude does. The local model is armed only through a small env file that the claude-local wrapper reads, scoped to that one invocation.

That boundary is load-bearing rather than stylistic: a global redirect would hijack every Claude Code session on the machine — including the one doing the work.

Two Codex landmines

Some provider ids are reserved built-ins — redefining ollama makes Codex reject the whole config, breaking even unrelated invocations, so reserved names get a -local suffix automatically. And wire_api must be "responses"; "chat" was removed in Codex 0.148.

Writes are atomic

Every config write goes to a temp file in the same directory and is renamed into place, with one dotfile backup kept beside the original. It's a dotfile on purpose: some of these live in directories a backend scans for its own configs, where a visible sibling gets picked up as a bogus model entry.
